Commission history: finance corrects a channel commission by overwriting the order's figure, so the order only ever shows the newest number. The durable audit already kept both sides of every commission_save, but no page read it. The commission page now lists the newest fifty audit entries for the property, each showing the amount, invoice reference and settlement state before and after, plus who made the change and when. It is read-only: it displays the history and never posts to the books. The local reducer now writes the same before/after shape into its own audit, so both runtimes tell the same story.

Empty properties (the operator's own instruction): the system no longer assumes any room layout for anybody. A property is now something the operator describes, not something the system invents. property_create is a separate command handled before authorize(), because the caller cannot yet hold the property it is creating; it re-checks the administrator role itself, validates the name (1-80 chars) and code (2-40 of A-Z a-z 0-9 _ -), refuses a taken code, is idempotent by request key, grants the creator the property at once and writes one append-only audit row marked starterInventory:'empty'. The stored body is genuinely empty: zero room types, zero physical rooms, zero beds or sales units, zero orders. The settings page gained a three-language new-property panel and an explicit empty-state message; the catalogue note now reads that this property's room types, room numbers and beds are all entered by the administrator and that the system assumes no room count, replacing the old 'real 10-room / 30-bed layout unconfirmed' wording. seed() is untouched, so every existing property and everything on the live account is unchanged.

Three real faults were found while proving the empty path, each reachable by a person: (1) render() called preview() on a scope with no property, which throws 'Property required', so the very page a new property needs was the page it could not show; fixed with an explicit no-scope branch that renders an empty workspace. (2) The property <select> is rebuilt on every render, so its onchange binding was replaced with dead DOM and choosing a property did nothing; now a delegated listener on document. (3) switchProperty() called leaveDialogs() while the property picker itself was open and refused the switch as a busy save; the picker is now closed first, since choosing a property is a choice and not a save. An administrator with no property may now exist (createUser allows an empty property list for admin only) and read() answers a truthful empty workspace with noPropertyYet:true rather than an access error.
