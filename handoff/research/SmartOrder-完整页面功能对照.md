# SmartOrder 与 JOVIAN PMS 页面及功能对照

核查日期：2026-10-15。参考环境：Microsoft Edge，SmartOrder 已登录的 ISOLA KLCC 门店。

本轮已完成当前账号可见导航范围的页面功能对照：7个主菜单、60个末级菜单入口、24张经营/住宿/财务报表。这里的“完整”指覆盖清单完整，不表示所有套餐功能、所有状态下的弹窗或写入结果都已验证。受限项目与未执行的真实业务动作逐项列于文末。接口工具研究按用户要求单独后续处理。本轮不读取凭据、不捕获接口、不执行业务写入；不复制专有源码、品牌、模板文案或客人资料。只打开菜单及未提交的表单，未保存、未发消息、未改价库存、未执行门锁。

## 顶部工具栏补充：统一消息与多语言

本节补充侧栏菜单之外的全局入口；前述7个主菜单、60个末级入口及24张报表不包含顶部工具栏。此前消息设置的核查不能替代统一收件箱核查。当前补查已打开统一收件箱及语言菜单；其他顶部工具仍须逐项核查，不能据侧栏覆盖宣称整套界面全部完成。

### 多国语言

SmartOrder 顶部地球图标展开13种语言：English、日本語、简体中文、ภาษาไทย、繁體中文、한국어、Español、Français、Deutsch、Italiano、Português、Русский、Bahasa Indonesia。本轮只展开菜单，未切换，尚未验证各业务页翻译覆盖率、语言偏好保存范围及日期数字格式变化。菜单未见 Bahasa Melayu；印尼文不能替代马来文。

JOVIAN 必须支持可扩展的多国语言选择，首批完整覆盖简体中文、English、Bahasa Melayu。v0.3 已有三语切换基础，不能据此认定未来全部模块已翻译。后台界面语言、客人网页/自助入住语言、消息模板语言分别管理；切换不得清空表单或改变业务数据。菜单、表单、弹窗、验证错误、订单状态、财务报表、打印及通知均纳入翻译覆盖；日期、时间、金额与币种按明确区域规则展示。新增语言通过资源字典扩展，避免业务代码内散落硬编码；缺失词条须有回退。是否加入其余语言按运营需求排期，不以其他语言替代马来文。

验收：同一账号切换三语后跨模块仍保持选择；同一订单数据金额与日期含义不变；未提交输入不丢失；客人语言独立于员工界面语言；长文案不遮挡按钮；空白、异常和权限受限页面亦完整翻译。

已实际打开顶部带未读数字的消息图标。界面为浮动窗口：左侧会话列表、右侧消息与回复区域；顶部还有语言/翻译样式图标、放大、最小化和关闭图标。其中语言/翻译图标的具体行为尚未验证，不能当作已支持自动翻译。

| 项目 | 本次可见证据 | JOVIAN 要求及边界 |
|---|---|---|
| 搜索与筛选 | 搜索客人姓名/订单号；所有渠道、已读状态、订单状态、房型、清空筛选 | 多门店权限内统一检索，保留渠道及原订单关联 |
| 渠道选项 | Booking.com、Expedia、Airbnb、Trip.com、TuJia、XiaoZhu、Booking Engine、SelfCheckin | 选项存在不代表本店全部连接成功，更不代表每个渠道均可双向回复 |
| 已读筛选 | 全部、未读、已读 | 未读数量、阅读状态与多人协作规则明确；不要混淆渠道已读回执与员工已读 |
| 订单筛选 | 全部、预订前、待处理、已确认、已取消 | 支持订单前咨询及取消后会话，不能只保留有效订单 |
| 会话摘要 | 客人、渠道徽标、订单状态、最新消息摘要、日期及部分未读数量 | 以渠道会话ID和门店隔离，避免同名客人串单 |
| 订单上下文 | 关联房源、入住离店日期、房型、订单明细入口 | 侧边可查看订单及住宿资源；回复前明确当前门店、渠道、收件人 |
| 消息内容 | 按日期展示消息及预订确认/取消等事件 | 区分客人消息、员工回复、自动消息与订单事件；保留原文与来源 |
| 回复框 | 文本输入、表情、快捷回复、图片附件、发送；空内容时发送禁用 | 明确发送中/成功/失败，防止重复发送，失败可重试且有操作记录 |
| 快捷回复 | 已打开选择弹窗：标题、消息、操作列，管理入口；提示发送前可编辑，当前列表为空 | 结合已核查的快捷回复设置，按语言选模板，替换变量后由员工确认内容 |
| 图片附件 | 前端文件选择器接受 PNG、JPEG、GIF，允许多文件 | 仅证明前端接受类型；渠道文件限制、大小、发送结果与安全处理未验证。本轮未选文件、未上传 |
| 连接提示 | 窗口明确提示：请直连到 Airbnb 和 Booking.com 以同步消息 | 这是 SmartOrder 本身条件提示，不能推导 JOVIAN 必须逐平台直连；JOVIAN 仍按付费渠道服务商路线，选型须确认消息能力 |

本轮未输入、发送、编辑或撤回任何客户消息；未验证真实发送、送达、附件传输、翻译及全部渠道连通。打开会话可能触发产品自动阅读状态，不能承诺阅读绝无状态副作用；未主动执行批量已读。

JOVIAN 将“多 OTA 统一收件箱”列为独立业务模块，与渠道订单/房价库存同步分别验收。渠道服务商评估必须包含：支持哪些平台的收件和回复、历史消息、附件、订单前咨询、Webhook或同步延迟、授权方式、平台限制、费用与失败重试；不假设有订单接口就有消息接口。自助入住与门店网页消息需能关联同一订单，但不把不同渠道身份自动合并。

v0.3 无真实消息收发及共享后端。先独立实现本地模拟会话、筛选、订单上下文、模板与发送状态测试，再接已确认能力的付费渠道服务商；模拟发送必须明显标识，不能显示为真实 OTA 已送达。正式多人使用需门店权限、回复归属、并发防重复、审计及敏感信息保护。

### 客户服务和帮助中心

已核查顶部耳机入口，菜单有“客户服务”“帮助中心”。客户服务打开联系面板，展示联系邮箱及服务时间；本轮未联系或发送消息。帮助中心另开公开页面 https://www.smartorder.ai/resources/support/ ，含文章搜索、热门文章，以及 Getting Started、Channel Manager、Reservation、Booking Engine、Payment、Setting 六类文章入口。只参考信息架构，不复制其文章或客服联系方式用于 JOVIAN。

JOVIAN 明确纳入两个常驻入口：客户服务、帮助中心。后台客户服务面向运营同事与现场人员，提供问题反馈、问题分类、关联门店/订单及处理状态，联系方式与服务时间可配置；初期可使用简洁反馈流程，不假称已有全天候客服。帮助中心按上手、房态与床位、订单入住退房、清洁维修、收退款与押金、财务、渠道消息、自助入住、权限设置分类，支持搜索和当前页面关联帮助，首批中英马来文。内容必须原创并对应实际功能。

客人端门店网页和自助入住页另提供联系门店、入住/退房指引、常见问题与报修求助；客人咨询可关联统一收件箱与订单，但系统使用支持、门店对客服务、OTA会话应明确标识，避免信息发错对象。电话、营业时段、紧急联系规则及可用沟通渠道均待门店确认，不自行填入承诺。v0.3 尚无上述完整能力，列为待实现需求。

验收：后台任意主要页面可达客服和帮助；搜索能找到相关三语内容；客人不暴露后台内部帮助、工单或其他客人订单；提交问题前明确发送对象及内容；联系入口显示实际服务时间，失败状态清楚。

- **页面实见**：已打开并读取该页面或弹窗；只能证明字段和入口存在。
- **入口实见**：只核实导航或权限树中的入口，不据此推断内部实现。

- **不采用**：按用户业务约束排除；仍记录参考系统的对应能力。
