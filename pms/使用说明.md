# 0.8.0 本地新增操作（2026-10-27，尚未部署）

7. 日历“订单盒子”查看盒内住宿项，勾选后恢复预订，可选恢复并自动分房。恢复重新检查房型容量，原房号不会自动保留；任一冲突整批不保存。也可从主单或单个住宿项恢复。
8. 订单列表按库存归属筛选占库存、盒内、已释放；盒内／恢复记录在详情操作记录中可查。取消盒内项仍需独立处理取消费用及退款。

本轮98项Node＋5项Python及进程内DOM验证通过，真实Edge和手机操作仍待实机验收。当前不能直接创建超容量盒内订单，也没有OTA自动入盒。分段换房、完整价格／财务、网站自助入住聊天和外部接入继续待做。

# JOVIAN PMS 本地测试使用说明

版本：0.3。适用：运营同事试用。JOVIAN酒店式公寓与CO-HUB青旅共用本系统。

这是操作原型，不是营业系统。仅录入虚构客人，勿录入真实姓名、证件、电话或付款资料。不会连接OTA、门锁、支付或线上官网。

## 一、第一次打开

1. 解压整个测试包，不要只取出HTML文件。
2. 电脑安装Python 3。安装后也可直接双击包内START-WINDOWS.bat启动，不必手输命令。Windows安装时勾选“Add Python to PATH”。如公司电脑限制安装，先联系系统负责人。
3. 进入解压后的JOVIAN-PMS文件夹，该目录应同时包含web、src和README.md。
4. 在此文件夹打开终端：Windows可在文件管理器地址栏输入cmd并回车；macOS可在终端输入cd后拖入该文件夹并回车。
5. 输入命令并回车：

```sh
python -m http.server 8010 --bind 127.0.0.1
```

Windows如提示找不到python，试用`py -m http.server 8010 --bind 127.0.0.1`；macOS可试用`python3 -m http.server 8010 --bind 127.0.0.1`。

6. 保持终端打开，在同一台电脑的Chrome或Edge浏览器访问：

http://127.0.0.1:8010/web/

不要直接双击index.html。这个地址只在运行命令的电脑上有效，不能发给别人当在线测试链接。手机也不能用这个地址访问电脑。

## 二、认识界面

- 左侧：多日房态、房态总览、订单管理、清洁与维修、操作记录。
- 右上角：切换测试门店、中文/英文/马来文。
- 模拟营业日期：测试时人为指定的日期，不是电脑今天的日期。
- 新建测试订单：每次创建一间房或一个床位。

测试店Kuala Lumpur：合成10间房＋30床；Penang：合成2间房＋6床。房型、房号、分区和门店布局仅用于演示，不是实际运营库存。房间和床位是两类销售单位，“40”不是40间房。

宿舍D1、D2为女士区；D3、D4为男士区；D5不限。此分区仅属于测试布局。

## 三、完整测试一遍（约10分钟）

### 1. 新建订单

1. 选择TEST · Kuala Lumpur，模拟日期设为2027-01-10。
2. 点击“新建测试订单”。
3. 姓名填写“测试客人A”；销售类型选“床位”；分区资格选“女士”。
4. 入住日期2027-01-10，退房日期2027-01-11；同房组编号留空。
5. 确认后进入“订单管理”。订单应显示“待入住”，已分配资源显示“—”。

订单即使没有人工分床，也已经占用库存；系统内部预留的床不代表已通知客人的床号。

### 2. 分床和入住

1. 在该订单的资源下拉框选择D1 · B1。
2. 点击“分配 / 换床”。仅选择下拉框不会保存。
3. 点击“办理入住”，状态应变成“在住”。

若目标床未清洁或分区不符，系统会拒绝。入住时模拟日期必须在入住日及离店日前。

### 3. 换床

1. 在同一订单下选择D1 · B2，再点击“分配 / 换床”。
2. 订单应显示新床位；原来的B1应转为“待清洁”。
3. 在“操作记录”查看本次操作。

这一版按整个住宿区间检查目标床。正式版按实际换床时刻拆段的能力尚未实现。

### 4. 退房与清洁

1. 模拟日期改为2027-01-11，即该订单离店日期。
2. 进入订单管理，点击“办理退房”，状态应变为“已退房”。
3. 进入清洁与维修，B2应为“待清洁”。
4. 对已空出的B1、B2点击“完成清洁”，状态恢复可用。

当前不支持提前/延迟退房。退房不自动完成清洁；本版本只有测试账务，退房前要把房费待收/待退及押金余额处理为零。

### 5. 维修停用

在“清洁与维修”选择一间空房，点击“停用当日”，应显示“维修停用”，当晚可售数减少。点击“解除停用”后恢复。此功能仅停用所选模拟日期的一夜；已固定分配的冲突资源不能直接停用。

### 6. 刷新、切店与语言

- 刷新页面，测试订单仍应存在。模拟日期会恢复默认值，需重新选择。
- 切换Penang，不应显示Kuala Lumpur的订单。
- 依次切换英文、中文、马来文，检查操作文案是否可理解。

## 四、建议再测的异常情况

| 测试 | 预期 |
| --- | --- |
| 女士订单分配到D3男士床位 | 拒绝，原订单不改变 |
| 两笔相同日期订单分配到同一床 | 第二笔拒绝 |

测试“强制同房”时用唯一编号，例如TEST-GROUP-01；不同团队不要重复用同一编号。每次仍只新建一床，不支持一次批量建多人订单。

## 五、常见问题

**页面打不开**：确认终端仍在运行、地址带/web/、命令在正确文件夹执行。若显示文件列表而不是界面，进入web/。

**提示端口被占用**：若已经启动过本程序，先使用原终端；如需另一个端口，命令里的8010改为8011，浏览器地址也改成8011。不同端口会使用不同的浏览器存储，看不到原端口的测试订单。

**新订单被拒绝**：检查日期、销售类型、分区、强制同房编号和连续库存。退房日期必须晚于入住日期。不限/未指定不会自动取得男女专属区资格。

**入住被拒绝**：确认已点击分配保存、床已清洁、模拟日期正确、前一客人已经退房。

**找不到昨天测试的数据**：确认使用同一浏览器、同一地址、同一端口和正确门店；无痕模式、清除站点数据或更换电脑都会影响保存。

**误录后想修改或取消**：本版可在订单详情修改或取消，也可导出测试订单CSV；尚无导入、一键重置或完整备份。确需清空可在浏览器设置里清除127.0.0.1的站点数据，这会不可恢复地删除该站点本地资料，执行前先保存所需反馈。

**如何关闭**：回到运行命令的终端，按Ctrl+C。正常关闭服务器不会主动删除浏览器内订单。

## 八、0.3新增功能怎么测

1. 多日房态默认显示从模拟日期开始的14天。点击空格可直接给指定房床建单；点击已有订单打开详情。横向滚动查看后续日期，纵向滚动查看床位。虚线订单是系统内部预留，尚未人工分配。
2. 创建订单时填写每晚测试房费、来源、备注；总费用按晚数计算，不自动加未确认税费。
3. 在详情修改离店日即测试续住；若固定房床已被下一单占用，应拒绝且原订单不变。在住订单不能改入住日。
4. 在收付记录依次选择“记录收款”“收押金”，输入金额和收付方式。押金不会抵减房费待收。所谓OTA代收也只是手工记录，不会查询OTA是否到账。
5. 试着退超过已收金额，系统应拒绝；退押金同样不能超余额。正常退房前记录尾款、处理多收退款并退还押金，全部余额为零才可退房。
6. 未入住订单可取消，必须填写原因及取消后的最终住宿费用（例如按测试政策填0）。取消后库存释放，已收的钱不自动退；仍需在详情记录退款和退押金。
7. 详情可锁定已分配房间，锁定后换房应拒绝；解锁后再操作。
8. 多日房态右上角可导出当前门店测试订单CSV；它仅含订单汇总，不是完整备份。

金额仅用MYR测试，最多两位小数。不能把本地流水当真实扣款、退款回执或营业财务账。
