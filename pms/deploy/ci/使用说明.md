# 长期自动更新 PMS 测试站

“首次配置一次”指建立部署通路。后续可以持续改进、反复部署；每次不用下载上传、也不用保持电脑登录。

## 分支及范围

GitHub仓库Popo841103/codex-pan，长期测试分支jovian-pms-test。推送该分支的pms/或工作流改动自动运行测试，成功后才更新https://pms.jovianhome.com/web/。没有部署密钥时只测试并注明“服务器未改动”。main、旧部署分支与官网保持不变。

## 首次连接

1. 在自己的PowerShell运行 `ssh root@207.148.78.107`。密码由本人输入，不发聊天。或使用Vultr已登录的root控制台。
2. 打开该分支的`pms/deploy/ci/BOOTSTRAP.txt`，复制整段命令（从python3到最后JOVIAN_SETUP）到服务器root终端并回车。此命令内含可审查的受限接收器、解包程序、更新器和安装程序，不下载外部脚本、不修改现有SSH登录方式、不部署业务代码。幂等安装并生成独立CI密钥。
3. GitHub仓库Settings → Secrets and variables → Actions → New repository secret，增加两项：
   - `PMS_SSH_KEY`：在服务器运行 `cat /root/.jovian-pms-ci/id_ed25519`，复制含BEGIN/END的全部内容到GitHub secret。私钥只放GitHub加密Secret，不截图、不发聊天、不提交到仓库。
   - `PMS_KNOWN_HOSTS`：复制安装输出的207.148.78.107开头的一整行。遗失可在服务器运行 `awk '{print "207.148.78.107 " $1 " " $2}' /etc/ssh/ssh_host_ed25519_key.pub`。必须取自已登录服务器，不从未经核实的ssh-keyscan接受新指纹。
4. 两项保存后告诉助手“两个Secret已设置”。助手推送下一次测试分支更新，触发首次部署；后续更新由同一流程反复执行。添加Secret本身不会自动重跑已完成的任务。
5. 查看仓库Actions中“JOVIAN PMS continuous test deployment”。测试和部署步骤全部成功才表示上线；如果只测试成功且提示缺Secret，服务器尚未更新。

## 长期运行

- 更新先做Node/Python测试，再经SSH传输代码；只上传PMS src/server/web/package.json。无订单数据库或凭据进入仓库、包或Actions日志。
- 独立SSH密钥受forced-command和restrict约束，只允许查PMS健康或上传PMS发布包，不开放交互shell、端口转发和SFTP。该密钥仍可部署PMS代码，须把分支写权限视作对PMS数据的管理权限。
- 根权限的接收器固定安装在服务器，不执行上传包中的shell脚本。包拒绝路径穿越、链接、数据库、无关目录及超限数据。
- 一次只进行一个部署；创建一致性SQLite备份，记录旧版本和新commit；只切换PMS代码和重启jovian-pms-test，不改Nginx、官网或Node系统版本。
- 健康检查失败自动切回旧代码，数据库不回滚。备份保存在/var/backups/jovian-pms-test，previous符号链接记录最近成功前的版本。
- 自动回退不等于任意版本兼容。未来数据库迁移须单独设计兼容及恢复方案。当前0.5沿用现有schema。
- 日常版本推送由助手继续办理。GitHub Actions可能受账号额度和计费限制；不保证无限免费。
- Windows不需要一直开机。手机PWA与此更新同一套服务，安装和触屏交互仍需实机验收。
- 服务器换机、密钥轮换、信任指纹或接收器本身变化时需更新相应配置；这不是每次发布都要重复的操作。

## 当前限制

尚未由GitHub runner实际连通Vultr；首次初始化和Secret配置需用户本人在其已授权终端与GitHub设置内完成。助手不能替用户写GitHub Secrets。设置完成后才能验证SSH防火墙、Actions权限和实际部署。不能把本地脚本通过测试说成线上已更新。SmartOrder全部功能对齐、GUI验收、正式营业上线仍分别推进。
