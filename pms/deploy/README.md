# 独立测试环境部署

状态：准备文件，未实际部署。目标服务器、测试域名及授权连接方式待确认。此方案部署完整Node.js＋SQLite服务，不是仅发布静态网页。Sites的Workers环境不直接支持当前node:sqlite/本地文件数据库，不能上传静态页面后声称共享后台已部署。

## 隔离边界

独立目录 `/opt/jovian-pms-test/`、服务 `jovian-pms-test`、用户 `jovian-pms`、数据目录 `/var/lib/jovian-pms-test/`、回环端口18010和独立HTTPS测试域名。既有官网 `/var/www/cohub`及餐饮供应链不变。实际服务器先只读检查端口、磁盘、Node路径、Caddy现有配置与备份策略，确认无冲突；不要直接覆盖Caddyfile或重启所有业务。

Node.js须24+，示例systemd使用`/usr/bin/node`，必须核对真实路径。数据库为单机开发阶段SQLite，不支持多实例共享文件或跨服务器副本。测试仅用合成数据，不能将当前版本切为营业主系统。

## 操作顺序（服务器访问可用后执行）

1. 在目标服务器确认Node.js24+、systemd和现有Caddy情况；记录现有业务健康状态与配置校验结果。
2. 上传经过测试的版本到`/opt/jovian-pms-test/releases/<版本>/`，不含.git、.data、*.sqlite或凭据；`current`软链接指向该版本。应用源码只读，数据目录归独立系统用户，权限0700。
3. 在独立数据目录初始化测试账号：工作目录设为该版本的pms，使用`PMS_DB=/var/lib/jovian-pms-test/jovian.sqlite node server/setup.js`。以服务用户执行，密码在交互提示输入，不放命令参数或配置文件。分别创建管理员、运营账号及授权门店；不得向聊天发送密码。
4. 将test.env.example替换为核实的独立域名、端口及数据库路径，再作为`/etc/jovian-pms-test.env`安装，仅管理员可写。示例域名不可直接上线。
5. 安装jovian-pms-test.service并检查Node路径与目录；仅启用这个新服务。它仍只监听127.0.0.1，不向公网开放18010。服务应以非root账号运行。
6. 先从服务器本机请求`http://127.0.0.1:18010/healthz`确认进程和数据库可读，再为确认的测试域名单独增加Caddy站点块。先备份并运行`caddy validate`，通过后reload；不替换其他站点，不使用全局stop/restart。
7. DNS指向目标服务器，验证证书与HTTPS域名；PMS_PUBLIC_ORIGIN须与该源一致。应用不信任客户端X-Forwarded-Host/Proto来决定授权源，HTTPS模式只接受配置域名，cookie带Secure。只允许该Origin的写入，并继续验证CSRF。
8. 验证未登录无法读订单、两账号共享读写、越权拒绝、退出失效、收款重试和服务重启后数据保留。再次检查原官网、餐饮供应链页面健康。GUI验证通过前明确标记未验证。

## 备份、恢复与回退

数据与代码版本分离，更新代码不能初始化覆盖已有数据库。冻结测试写入后可用SQLite一致性备份，或停止**仅PMS测试服务**后复制数据库并做恢复演练；不能只复制运行中WAL模式的主文件而遗漏未检查点数据。备份含账号哈希、会话与订单，必须限制访问，不能进源码包。

回退时仅停止PMS测试服务、切current到兼容的上个代码版本，再启动；不能覆盖数据库丢掉新增订单。若数据库schema发生变化，需先核对兼容迁移方案。本次schema仍为1，部署流程不自动降级或删除数据库。测试服务关闭不影响现有站点。

## 尚缺条件

本环境没有已配置的目标SSH连接、服务器凭据或目标域名；目前不能实际安装到Vultr。用户需确认目标与安全连接方式。权限用现有连接或平台密钥配置，不收正式密码、私钥或客人资料。没有真实域名/连接和远端成功检查，不应返回“已部署”或编造网址。

## 服务器实况修正（优先于上文的Caddy初始假设）

用户截图已证实公网80/443由Nginx监听，Node22服务已存在。部署PMS时新增独立Nginx站点，先查重复server_name，再验证配置并仅reload Nginx。Caddy片段仅作旧方案参考，不安装或启用。Node24隔离到专用路径，验证后调整systemd ExecStart，绝不原地替换/usr/bin/node影响现有Node3000服务。HTTPS模板仅在pms.jovianhome.com专用证书签发后启用；不得挪用cohub证书。

## 首次安装脚本

install-vultr-test.sh用于已登录的Vultr SSH终端，执行前审核。它仅支持首次安装，已有目录/域名配置或占用端口会停止；安装独立Node24、独立测试账号与systemd服务，新增Nginx站点并通过现有Certbot账户申请pms域名证书。不会替换/usr/bin/node或cohub配置，不主动接受新条款或注册新ACME账户。证书失败时撤下自己新增的Nginx站点；PMS目录和数据库保留以供排查，不保证完全回滚安装依赖。

脚本已通过bash语法检查，应用32项测试通过，尚未在目标服务器执行。不能把脚本存在当部署成功。代码可以通过已连接的私有GitHub仓库独立部署分支交付；不上传真实数据库、密钥、.git或生产网站目录。
